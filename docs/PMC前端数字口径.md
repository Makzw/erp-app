# PMC 界面数字口径：每个数字从哪来、怎么算

> 对象：`/home/Mak/erp-app`（端口 8001）PMC 三个界面上的**每一个数字**。
> 前端源码：`static/index.html`（`renderPMCList` / `renderPMCTree` / `pmcShowSummary`）；后端源码：`main.py`（`pmc_pos_unanalyzed` / `pmc_preview_mps` / `_calc_prd_summary`）。
> 配套文档：`docs/PMC计算逻辑.md`（后端算法全貌）。本文只讲「屏上这个数是怎么来的」。

---

## 0. 数据流水线（三段）

```
 ① 待分析单列表                    ② BOM 树（点一张卡片）              ③ 品号汇总（按钮）
 /api/pmc/pos_unanalyzed     →    /api/pmc/preview_mps          →   /api/pmc/prd_summary
 VW_POS 筛出待排产的行           展开 BOM + 逐行算库存/在途/缺口        把②的结果按品号合并
 每行一个卡片                    每行 = BOM 一个节点                  每行 = 一个品号
```

- ①②是**实时**的（每次点都重新查库、重算），③是**缓存**的（后台算几十秒，TTL 10 分钟）。
- 前端**只做显示**：所有数字都来自接口返回的字段，前端不算业务值（唯一的前端计算是「缺口进度条百分比」和「净缺口合计」的求和）。

## 1. 列表页（待分析单）

| 屏上位置 | 值 | 来源 | 说明 |
|---|---|---|---|
| 卡片大数字（蓝色，18px） | `t.qty` | `VW_POS.QTY` | **订单量（原始）**，不减已出货 |
| 下面那个小字「件」 | 写死 | — | 只是单位字样，不参与计算 |
| 第一行灰字 | `t.os_no` | `VW_POS.OS_NO` | 销售订单号 |
| 第二行加粗 | `t.prd_no` | `PRD_NO` | 成品品号 |
| 第三行 | `t.prd_name` | `PRD_NAME` | 品名 |
| 灰 chip / 黄 chip | `cus_name` / `指令单号` | `CUS_NAME` / `指令单号` | 客户、指令单 |
| 右上「已选 N / M 条」 | `pmcSelected.length / items.length` | 前端计数 | M = **全量**（搜索不过滤这个分母） |
| 搜索框 | 前端过滤 | — | 只过滤显示，不影响已选、不影响 M |

选中一张卡片 = 往 `pmcSelected` 里压 `{so_no_itm, so_no, prd_no, qty}`（`qty` 就是卡片上那个订单量，传给后端只当**兜底**，见 §3.1）。

> ⚠ 卡片上的大数字（订单量）和树上成品行的「需求」（销售未出）**不是同一个数**：部分出货过的单，卡片 2,000、树上需求 1,400 是正常的。

## 2. BOM 树页（点开一张卡）

### 2.1 顶部两个标签

| 标签 | 算法 |
|---|---|
| 红标「缺 X 件 · Y 项缺口」 | `X = Σ gap`（只累加 `gap > 0` 的行），`Y = gap > 0 的行数` |
| 绿标「✓ 全部充足」 | 所有行 `gap ≤ 0` |

> 这是**整张单所有节点**的加总（成品行也算），只是给个总量感，**不是下单依据**（下单看品号净缺口）。

### 2.2 表格 11 列，逐个说

| 列 | 前端取值 | 后端字段 | 怎么算出来的 |
|---|---|---|---|
| **品号** | `r.prd_no` + `r.prd_name` | `prd_no / prd_name` | 来自 BOM 树节点；成品行 = 销售订单的品号 |
| **层** | `is_fg ? '成品' : 'L'+depth` | `is_fg / depth` | 成品 = L0；子件逐层 L1…（颜色 5 档：蓝/绿/橙/深橙/红） |
| **需求** | `Number(r.real_demand)` | `real_demand` | 成品行 = **销售未出**（`QTY − SAQTY`）；子件行 = **父件缺口 × 配比**（配比 = BOM.用量 ÷ 基数） |
| **销售未出** | `so_remain` | `so_remain` | `QTY − SAQTY`，**只有成品行有**，其他行显示 `-` |
| **原材料仓** | `r.mat_qty` | `mat_qty` | 该品号**除生产仓外**所有仓的现存量之和（可点 → 调整弹窗） |
| **生产仓** | `r.prod_qty` | `prod_qty` | 该品号在 `ATTRIB ∈ {5,6}`（车间仓+外发仓）的现存量之和（不可调） |
| **在途采购** | `r.pool_way` | `pool_way` | **全厂**在途采购（该品号所有未回采购，含别的单已下的；tooltip 显示「其中挂本单 X」） |
| **在单请购** | `r.pool_odr` | `pool_odr` | **全厂**在单请购（该品号所有未转采购的请购） |
| **合计** | `r.pool_total` | `pool_total` | **= 在途采购 + 在单请购**（不含库存） |
| **缺口** | `r.net_gap` + 进度条 | `net_gap` | `需求 − 合计(池) − 库存`，**下单口径**；`> 0` 红字+条，`≤ 0` 显示绿 ✓ |
| **调整** | 按钮 | — | 成品行不显示；点开弹窗改**原材料仓**库存（写 IC） |

**显示规则（容易以为算错的）**
- 数字用 `toLocaleString('zh-CN')` → 带千分位（`8,000`）。
- `销售未出 / 在途采购 / 在单请购` = 0 时显示 `-`（不是 0）。
- `需求 / 原材料仓 / 生产仓 / 合计` = 0 时显示 `0`。
- 行底色：成品行淡蓝；非成品行 `gap > 0` 淡黄（其他白）。
- **缺口进度条** = `min(100, round(合计 ÷ 需求 × 100))%` —— 是「供给占需求的百分比」，条越长=越够；颜色 `gap>0` 红、否则绿。需求为 0 时条为 0。

### 2.3 「品号净缺 X」小字（缺口列第二行）

- 值 = `r.prd_net`（品号汇总缓存里的净缺口）。**只有它和本行「缺口」不同时（同品号多单/同单多行）才显示**，避免重复噪音。
- 悬浮 tooltip 展开算式：`该品号跨 N 张待分析单：需求合计 X − 在途/在单请购 Y − 库存 Z = 净缺口 W`。
- `prd_net ≤ 0` 显示 `品号净缺 0`（绿色）。

### 2.4 底部说明栏

口径速查：`销未出=销售未出`、`在途=全厂在途采购（含别的单已下的）`、`在单请购=全厂在单请购（含别的单已请的）`、`合计=在途+在单请购`、`缺口=需求−合计−库存（这就是该买多少；同品号多单时看品号净缺）`。

### 2.5 调整弹窗（点「原材料仓」单元格或「调整」按钮）

| 位置 | 值 | 来源 |
|---|---|---|
| 原材料仓明细列表 | `仓码 仓名: 现存量` | 行里的 `mat_detail[]`（= `wh_detail` 里 `is_prod=false` 的仓），元素 `[仓码, 仓名, 现存量, 可用量, 在途, 在单]` |
| 目标仓库 | 下拉/手输 | `mat_detail` 的仓码做 datalist；切换仓会**把数量框重置为该仓现存量** |
| 调整后数量 | 手填 | **空 = 未填（拦）**；显式 `0` = 清仓（放行）；提交后后端写 IC（`0` 出库/`13` 入库，数量取差额绝对值） |

### 2.6 行的完整字段（前端只用了其中一部分）

```
prd_no prd_name is_fg depth knd real_demand so_remain gap          ← 显示用
qty（=销售未出兜底） qty_on_way qty_on_odr total_avail total_stock ← 显示用
mat_qty prod_qty mat_detail[] prod_detail[]                        ← 显示 + 调整弹窗
pool_way pool_odr                                                  ← 只进 tooltip
raw_stock contribution wh qty_wh qty_av                            ← 旧版字段，现在前端不用
prd_net prd_need prd_stock prd_orders                              ← 品号汇总缓存（热了才有）
```

## 3. 「缺口」和「品号净缺」什么关系（关键）

**两者是同一个算式**：`缺口 = 需求 − 在途/在单请购(全厂池) − 库存`。差别只在**去重范围**：

- **树上「缺口」（行级）**：只看这一行（一张单里的一个节点）
- **品号汇总「净缺口」（品号级）**：跨所有待分析单合并需求，池子和库存各只扣一次
- 单张单用到的料两者相同；同一个品号被多张单用到时行级会各扣一遍 → 以品号净缺为准（不一致时缺口列下面会多显示一行「品号净缺 X」）

真实例子（`SO26090029004`，2,000 件）：

| 料 | 需求 | 在途/在单请购 | 库存 | 缺口 | 含义 |
|---|---|---|---|---|---|
| `RM01C2362.0` | 164 | 0 | 3,333 | **0** | 仓库够 → 不用买 |
| `P20610-01-03` | 8,000 | 0 | 56,700 | **0** | 仓库够 → 不用买 |
| `SC0037-ZN` | 16,000 | 45,612 | 17,500 | **0** | 别的单已经买了 45,612 在途/在单请购 → 不重复买 |

**「昨天买了 7000，今天只买 3000」就是这么算的**：
`净缺口 = 今天总需求 10,000 − 昨天已买（在途池）7,000 − 库存 = 3,000`

### 3.1 三个「数量」别搞混

| 名字 | 定义 | 用在哪 |
|---|---|---|
| **订单量** `qty` | `POS.QTY` | 列表卡片大数字；选中时传给后端只作兜底 |
| **销售未出** `so_remain` | `VW_POS.QTY − VW_POS.SAQTY`（v2 视图 `QTY_ON_ODR` 的口径；`QTYPS` 是废列） | 树上成品行「需求」、销未出列；**真正参与计算的需求基准** |
| **需求** `real_demand` | 成品=销售未出；子件=父件缺口×配比 | 树上「需求」列、缺口算式左边 |

### 3.2 「合计」不是库存

`合计 = 全厂在途采购 + 全厂在单请购`，**不含库存**。库存单独两列（原材料仓/生产仓），`缺口 = 需求 − 合计 − 库存`。

## 4. 品号汇总页（点工具栏「品号汇总」）

| 屏上位置 | 值 | 来源 |
|---|---|---|
| 顶部「基于 N 张待分析单、M 个品号，算于 HH:mm:ss」 | `d.orders / d.items.length / d.ts` | 接口元信息 |
| 算式说明那行 | 写死文案 | — |
| **品号 / 品名** | 品号 | 汇总的 key |
| **需求合计** | `Σ real_demand`（该品号在所有待分析单里） | 后端 |
| **在途+在单请购** | `pool`（全厂在途采购池 + 在单请购池） | 后端；>0 橙色 |
| **库存** | 原材料仓 + 生产仓（现存） | 后端；负数红字 |
| **净缺口** | `max(0, 需求合计 − 在途/在单请购 − 库存)` | 后端；= 0 的行整行 55% 透明、显示 `—` |
| **单数** | 该品号出现在几张单里 | 后端 |
| 底部「净缺口合计：X 件」 | `Σ net`（前端求和） | —— |
| 「重算」按钮 | `?refresh=1` 强制重算 | —— |
| 「汇总计算中…」 | `d.computing = true` 时，每 6 秒轮询一次 | 后台线程算完自动出 |

排序：净缺口降序（`net > 0` 在前）。**这一列就是拿去下采购/请购的数**。

## 5. 想核对某个数时怎么做

```bash
# ① 把树上每个字段原样拉出来（成品行 + 所有子件）
curl -s "http://127.0.0.1:8001/api/pmc/preview_mps?so_no_itm=SO26090029004&prd_no=0067(605569/851391)&qty=2000" | python3 -m json.tool | head -40

# ② 品号汇总（加 refresh=1 强制重算）
curl -s "http://127.0.0.1:8001/api/pmc/prd_summary?refresh=1" | python3 -m json.tool | head -40

# ③ 全量自检：按独立实现逐行验「需求=父件缺口×配比」「缺口=需求−合计」
cd /home/Mak/erp-app && env -u PYTHONPATH /usr/bin/python3 pmc_formula_check.py
```

屏上对不上时先看三处：① 卡片数是**订单量**、树上是**销售未出**；② 在途/在单**只算挂本单的**（没挂上的料在 tooltip 里会写「池 X，挂的是别的单」）；③ 净缺口只有汇总缓存热了才显示。
